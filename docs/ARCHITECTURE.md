# Архитектура CRM ИТ Школы

Исходная Archi-модель: `docs/architecture/CRM-IT-School.archimate`. Откройте
её в Archi через **File → Open**; модель содержит функциональный и
компонентный слои, внешние зависимости и связи между ними.

## Функциональная архитектура

Пользователь управляет каталогами, вузами и карточками взаимодействий. Карточка
ведётся по версии workflow: этапы, допустимые переходы, история и вложения.
Отдельные функции — импорт Excel, отчётность, интеграции, уведомления, чат и
образовательные активности. Keycloak отвечает за идентификацию и роли, а аудит
фиксирует изменения и выгрузки.

## Компонентная архитектура

```text
Browser → React SPA / Nginx → FastAPI API → PostgreSQL
                                  ├──────→ MinIO (вложения)
                                  ├──────→ Redis (опциональный кэш)
                                  ├──────→ Keycloak (JWT/JWKS)
                                  └──────→ LMS/CMS и каналы уведомлений
```

SPA работает с API только по same-origin. API является единственной точкой
доступа к БД и MinIO, применяет область видимости пользователя на уровне
репозиториев и записывает аудит. Бизнес-правила находятся в сервисах, а HTTP
контракты — в схемах и роутерах; это позволяет подключать импорт и интеграции
без обхода проверок.
