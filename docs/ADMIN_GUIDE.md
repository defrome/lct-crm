# Руководство администратора

Краткая справка доступна в приложении: **Помощь → Администратору**. Этот
документ предназначен для сопровождения контура и описывает фактическую
конфигурацию проекта.

## Перед запуском production-контура

1. Скопируйте `.env.server.example` в серверный `.env` и замените все
   `change-this-*` значения. В production обязательны `AUTH_MODE=keycloak` и
   непустой `AUDIT_HASH_KEY`.
2. Подготовьте DNS для `DOMAIN`, `KEYCLOAK_DOMAIN` и `GRAFANA_DOMAIN`. Caddy
   выпускает HTTPS-сертификаты и отдаёт SPA/API на `https://DOMAIN`; Keycloak
   для браузера также доступен на `https://DOMAIN/kc`.
3. Создайте отдельный production realm либо используйте поставляемый
   `crm-production` только как стартовый шаблон. Проверьте redirect URI и web
   origin клиента `crm-web`; `keycloak-bootstrap` сверяет их при развёртывании.
4. Размещайте `.env` и секреты вне Git. Это относится к PostgreSQL, MinIO,
   Keycloak, Grafana, `AUDIT_HASH_KEY`, SMTP и токенам LMS/CMS.
5. Согласуйте исходящий доступ к LMS/CMS, SMTP и Telegram. До этого оставьте
   `INTEGRATIONS_MODE=fixture` и внешние каналы выключенными.

Запуск production Compose:

```bash
docker compose -f docker-compose.deploy.yml up -d --build
docker compose -f docker-compose.deploy.yml ps
```

Проверьте `/health`, вход пользователем каждой роли и доступ к приложению по
HTTPS. Инфраструктурные сервисы в deploy Compose доступны только из внутренней
сети; Mailpit UI намеренно привязан к `127.0.0.1:8025`.

## Роли, сотрудники и область видимости

Keycloak является источником ролей. API создаёт или обновляет локальную
проекцию пользователя при аутентификации для назначений, уведомлений и аудита.

| Роль | Доступ |
|---|---|
| `user` | Назначенные вузы и связанные карточки; область можно дополнительно сузить режимом `selected`. |
| `manager` | Все рабочие данные, справочники, workflow, импорт, отчёты и правила уведомлений. |
| `admin` | Возможности manager, пользователи, область видимости КАМов и журнал аудита. |

Роли изменяются в Keycloak. В CRM администратор может обновить Telegram ID
сотрудника и его режим видимости (`assignments`, `selected`, `all`), но не
должен использовать локальную запись для назначения роли. После смены роли
пользователь должен получить новый токен: выйти и войти снова.

## Флаги и каналы

| Переменная | Значение |
|---|---|
| `CACHE_ENABLED` + `FEATURE_CACHE_ENABLED` | Включают Redis-кэш каталогов. |
| `FEATURE_CHAT_ENABLED` | Включает сообщения и вложения в карточках. |
| `FEATURE_NOTIFICATIONS_ENABLED` | Запускает worker, создание напоминаний и outbox. |
| `FEATURE_EXTERNAL_CHANNELS_ENABLED` | Разрешает попытки внешней доставки. |
| `NOTIFICATIONS_POLL_SECONDS` | Интервал worker, не менее 10 секунд; по умолчанию 60. |

Уведомление не блокирует переход карточки: сначала сохраняется запись outbox,
затем worker пытается доставить её. Email использует `SMTP_*`; для Telegram
нужны `TELEGRAM_BOT_TOKEN` и Telegram ID получателя (или общий
`TELEGRAM_CHAT_ID` для системной доставки). Доступные каналы правил — `email`
и `telegram`.

## Файлы, импорт и резервные копии

MinIO хранит файлы импорта, вложения этапов и чата. PostgreSQL содержит их
метаданные и ключи объектов. Не делайте bucket публичным: выдача файлов идёт
через API после проверки области видимости.

Резервная копия должна включать PostgreSQL и MinIO как согласованную пару,
плюс серверный `.env` или независимое безопасное хранение секретов. Перед
вводом в эксплуатацию выполните проверочное восстановление. Мягкое удаление
записи или файла не является политикой физического удаления; срок хранения и
регламент очистки должны быть утверждены владельцем данных.

## Контрольный лист

- [ ] Заменены демонстрационные пароли и `AUDIT_HASH_KEY`.
- [ ] Проверены realm, роли, redirect URI, web origin и повторный вход после смены роли.
- [ ] Внешними портами остаются только 80/443; административный доступ идёт через VPN/внутреннюю сеть.
- [ ] Проверены backup и восстановление PostgreSQL с MinIO.
- [ ] Реальные интеграции включены после проверки контракта, TLS/VPN/proxy и allowlist.
- [ ] Email/Telegram проверены тестовой доставкой; Mailpit не принимается за боевую почту.
