# Руководство администратора

Краткая версия доступна в приложении в разделе «Помощь → Администратору».
Этот документ — эксплуатационная инструкция для закрытого контура.

## Закрытый контур и запуск

1. Создайте отдельный production realm и клиентов Keycloak. Демонстрационный
   realm из репозитория использовать в production нельзя.
2. Храните пароли PostgreSQL, MinIO, Keycloak, Grafana и токены интеграций в
   секрет-хранилище или вне Git. Подготовьте `.env` по `.env.example`.
3. Оставьте внешним только HTTPS-вход веб-приложения. PostgreSQL, MinIO, Redis,
   Prometheus и Grafana размещайте во внутреннем сегменте.
4. До запуска согласуйте DNS, сертификаты, VPN/proxy, mTLS (если нужен) и
   allowlist адресов LMS/CMS. Не включайте реальные интеграции без allowlist.
5. Запустите `docker compose up -d --build`, дождитесь health-check'ов и
   проверьте вход пользователем каждой роли.

Подробная схема reverse proxy и размещения сервисов находится в
`docs/SECURITY_AND_OPERATIONS.md`.

## Keycloak и роли

Keycloak — источник истины об учётной записи и роли. API создаёт локальную
проекцию пользователя для внешних ключей и аудита при первом входе.

| Роль | Полномочия |
|---|---|
| `user` | Только назначенные вузы, их карточки, маршрут, файлы и чат. |
| `manager` | Все карточки и каталоги, импорт, процессы, уведомления. |
| `admin` | Всё manager плюс пользователи, аудит и опасные операции. |

После смены роли выйдите и войдите снова, чтобы получить новый JWT. Не
назначайте роль только в локальной таблице: при следующей аутентификации её
перезапишет Keycloak.

## Feature flags, кэш и каналы

Все необязательные компоненты выключены по умолчанию. Для кэша нужны оба
флага: `CACHE_ENABLED=true` и `FEATURE_CACHE_ENABLED=true`. Кэшируется только
справочная информация; он не является offline-очередью и при ошибке Redis API
продолжает работать с PostgreSQL.

| Переменная | Что включает |
|---|---|
| `FEATURE_CHAT_ENABLED` | Обсуждения карточек и вложения сообщений. |
| `FEATURE_NOTIFICATIONS_ENABLED` | Worker правил и outbox уведомлений. |
| `FEATURE_EXTERNAL_CHANNELS_ENABLED` | Внешние адаптеры email, Telegram и MAX. |
| `FEATURE_CACHE_ENABLED` + `CACHE_ENABLED` | Redis-кэш каталогов. |

Для email укажите `SMTP_*`. Внешние каналы включайте только после сетевой
проверки: ошибка доставки не отменяет переход карточки, а попадает в outbox и
аудит. Параметры Telegram/MAX не размещайте в исходном коде.

## MinIO, файлы и резервное копирование

Новые вложения этапов и сообщений хранятся в MinIO, а PostgreSQL содержит их
метаданные и ключ объекта. Доступ к объектам проходит через API после проверки
прав на карточку; бакет не должен быть публичным. Скачивание фиксируется в
аудите. Срок хранения и физическая очистка файлов требуют отдельной политики
владельца данных — кнопка удаления не должна молча очищать MinIO.

В резервную копию включайте PostgreSQL и MinIO согласованно. Перед вводом в
эксплуатацию выполните тестовое восстановление обоих хранилищ.

## Контрольный лист администратора

- [ ] production realm, redirect URI и web origin проверены;
- [ ] секреты не попали в Git и не используются демонстрационные пароли;
- [ ] allowlist интеграций, VPN/proxy и TLS согласованы;
- [ ] тесты доступа user/manager/admin успешно пройдены;
- [ ] backup PostgreSQL и MinIO проверен восстановлением;
- [ ] уведомления и внешний канал включены только после тестовой доставки.
