## Как подключаться к существующему коду

Три вещи, которые экономят день на старте.

**Аудит достаётся бесплатно.** Унаследуй модель от `DomainBase` (`backend/app/models/base.py`) — получишь UUID-PK, `created_at/updated_at/created_by/updated_by`, мягкое удаление и автоматическую запись в `audit_log` на каждый insert/update. Ничего вызывать руками не нужно. Для не-ORM событий (переход по этапу, выгрузка файла) — `backend/app/services/audit.py::log_event`.

**Видимость достаётся бесплатно.** Если новая таблица привязана к вузу, задай в репозитории `university_scope_column = "university_id"` — и роль `user` автоматически будет видеть только свои записи. Фильтр живёт в `BaseRepository`, роутер про него не знает.

**Не затирай заполненное пустым.** Правило «пустая ячейка = нет данных» действует во всём импорте — см. `InteractionService.upsert`. Тот же принцип нужен переходам и интеграциям.

Полезные точки входа: `backend/app/services/catalogs.py` (find-or-create для всех справочников — вызывать из интеграций, а не дублировать), `backend/app/services/text.py` (нормализация названий), `backend/app/core/errors.py` (коды ошибок).

## Решения, которые принимает заказчик, а не разработчик

Пока не закрыты — держать на виду.

| Вопрос | Почему важно |
|---|---|
| Хеширование ПДн в аудите без соли | Несолёный sha256 телефона или email теоретически подбирается по словарю. Альтернатива — HMAC с ключом, но тогда хеши нельзя сравнивать между записями |
| Состав полей, отнесённых к ПДн | Сейчас `full_name`, `email`, `phone`. Если заказчик добавит, например, должность — это одна строка в модели |
| Срок хранения `import_rows` | Там лежат сырые строки Excel с ФИО контактов вузов. Автоочистки сознательно нет |
| Срок хранения вложений к этапам | Файлы лежат в БД бессрочно. Само место хранения выбрано (база, не том и не S3), автоочистки нет |
| Политика хранения файлов в MinIO | Для `F11–F12` нужно согласовать срок хранения, версионирование, резервное копирование и необходимость антивирусной проверки загружаемых файлов |
| `OPEN-01`, `OPEN-04` | Контракты API LMS и сайта, перечень полей JSON |
| Право переименования этапа | До отдельного решения реализовать только для `admin` (`A11`, `H-OPEN-01`) |
| Сетевой доступ к Telegram/MAX и email из закрытого контура | Определяет, какие адаптеры `H2` могут быть включены в демонстрации (`H-OPEN-02`) |
| Получатель напоминания по умолчанию | Предлагается ответственный и его руководитель; необходимо подтвердить (`H-OPEN-03`) |
| Формат чата | Для первой версии — текст; вложения и упоминания требуют отдельного решения (`H-OPEN-05`) |
