# CRM ИТ Школы Ростелекома — веб-интерфейс

Фронтенд к сервису CRM ИТ Школы: вузы, ИТ-продукты, карточки взаимодействий и
их путь по workflow, импорт каталогов из Excel, отчёты и журнал аудита.

Реализует `FR-13` (веб-интерфейс) и закрывает трек D бэклога бэкенда.

---

## Быстрый старт

> Часть монорепозитория. Обзор и запуск всего контура одной командой —
> в [README в корне](../README.md).

Нужен поднятый бэкенд: `docker compose up -d` в корне репозитория
(API на `:8000`, Keycloak на `:8080`, Postgres на `:5432`).

```bash
npm ci
npm run dev          # http://localhost:5173
```

Учётные записи из `../docker/keycloak/realm-export.json`:

| Логин | Пароль | Роль в системе |
|---|---|---|
| `kc-user` | `user123` | КАМ — видит только закреплённые за собой вузы |
| `kc-manager` | `manager123` | Руководитель — видит всё, назначает ответственных |
| `kc-admin` | `admin123` | Администратор — плюс удаление и журнал аудита |

Development realm также содержит 20 КАМов: `kc-user` и `kc-kam-02`…`kc-kam-20`.
Пароль для `kc-kam-02`…`kc-kam-20` — `kam123`; при первом входе он должен быть заменён.
Сидирование заранее добавляет их в локальную проекцию, поэтому они видны в разделе
«Сотрудники» сразу после запуска API.

### Почему всё идёт через прокси

API не подключает `CORSMiddleware`, а клиент Keycloak в реалме разрешает
единственный web origin. Поэтому и dev-сервер, и nginx в контейнере проксируют
оба бэкенда под своим origin: браузер делает только same-origin запросы, а в
коде живёт один набор относительных URL (`/api/v1/...`, `/kc/realms/...`).
Бэкенд для этого править не нужно.

## Сборка и запуск в контейнере

```bash
docker build -t crm-web .
docker run --rm -p 3000:80 \
  -e API_ORIGIN=http://host.docker.internal:8000 \
  -e KEYCLOAK_ORIGIN=http://host.docker.internal:8080 \
  crm-web
```

`API_ORIGIN` и `KEYCLOAK_ORIGIN` подставляются в конфиг nginx при старте
контейнера, пересобирать образ под другой контур не нужно.

Чтобы добавить фронтенд в `docker-compose.yml` бэкенда:

```yaml
  web:
    build: ../crm-lct-frontend
    container_name: crm-web
    depends_on: [api, keycloak]
    environment:
      API_ORIGIN: http://api:8000
      KEYCLOAK_ORIGIN: http://keycloak:8080
    ports:
      - "3000:80"
```

## Что есть в интерфейсе

| Раздел | Что делает | Требование ТЗ |
|---|---|---|
| **Обзор** | Сводка: сколько карточек, где они стоят по этапам, какие лицензии истекают, нагрузка по ответственным | `FR-02` |
| **Взаимодействия** | Список с фильтрами «период + вуз + направление + продукт + ответственный», сортировка, создание и правка карточек | `FR-01` |
| **Карточка взаимодействия** | Путь работы с вузом по этапам, переходы с комментарием, история перемещений, файлы на этапах | `FR-03`, `FR-04` |
| **Вузы** | Справочник, реквизиты, контактные лица, закрепление КАМов по периодам | `SRV-01` |
| **Справочники** | ИТ-продукты, ИТ-направления, вендоры, контакты вузов | `SRV-01` |
| **Процессы** | Создание и правка workflow: версии, этапы, переходы, публикация | `FR-07`, `FR-10` |
| **Импорт** | Мастер из пяти шагов: загрузка → маппинг → предпросмотр (dry-run) → запись → отчёт | `SRV-01` |
| **Отчёты** | Конструктор: отбор, выбор колонок, выгрузка в XLSX, PDF, CSV и JSON | `FR-05`, `FR-09`, `SOL-04` |
| **Сотрудники** | Проекция учётных записей Keycloak, роли | `FR-12` |
| **Журнал аудита** | Кто, когда и что изменил; фильтры по сотруднику, действию, объекту и периоду | `FR-08` |

### Роли

Разграничение зеркалит API: `user` видит закреплённые за собой вузы, `manager`
видит всё и меняет назначения, `admin` дополнительно удаляет и читает аудит.
Интерфейс скрывает недоступные действия, но источник истины — сервер: экран
роли не заменяет проверку прав.

## Решения, которые стоит знать при доработке

**Авторизация.** Keycloak, resource-owner password grant через прокси
(`src/api/auth.ts`). Форма входа живёт в приложении — это шаг 1 из `UX-PATH`
ТЗ. Токен обновляется заранее, за 45 секунд до истечения, поэтому длинная
сессия не выкидывает пользователя из наполовину заполненной формы. Переход на
redirect + PKCE меняет один модуль: заведите в реалме public-клиент с этим
origin в redirect URIs и замените `requestToken` на обмен кода — остальному
коду всё равно, каким грантом получен токен.

**Кэш (`FR-14`).** TanStack Query: открытые списки и карточки остаются
тёплыми, возврат на экран рисуется мгновенно и обновляется фоном. Ключи
собраны в `src/app/queryClient.ts`, чтобы инвалидация после мутаций не
разъезжалась.

**Фильтр по периоду.** В `/interactions` у API нет параметров периода (задача
B1 бэклога), поэтому период применяется на клиенте поверх полной выборки
(`src/lib/fetchAll.ts`). Для текущих объёмов это точно; когда параметр
появится на сервере, фильтр нужно перевести на него.

**Отчёты.** Эндпоинта отчётов на бэкенде нет (задача B2), файлы собираются в
браузере. XLSX — `exceljs`, PDF — `jsPDF` со встроенным Roboto
(`src/assets/fonts/`): у стандартных шрифтов PDF нет кириллицы, поэтому шрифт
обязан ехать внутри документа. Обе библиотеки грузятся только в момент
выгрузки.

**Диаграммы.** Одна серия на график, поэтому цвет кодирует величину, а не
принадлежность: один акцентный оттенок, без легенды, заголовок называет
величину. Палитра статусов проверена валидатором на различимость, а не на
глаз; красный и охра неразличимы при дейтеранопии, поэтому каждый статус
всегда несёт иконку и слово, а не только цвет.

**Поля маппинга импорта.** `src/features/imports/fields.ts` дублирует
`app/imports/mapping.py` бэкенда: API отдаёт только *предложенный* маппинг, но
не полный список полей. При изменении `FIELDS_BY_TARGET` на сервере нужно
поправить и этот файл.

## Стек

| Библиотека | Зачем |
|---|---|
| React 19 + TypeScript | `SOL-01` |
| Vite 8 | сборка и dev-сервер с прокси |
| React Router 7 | маршрутизация, состояние фильтров в URL |
| TanStack Query 5 | кэш запросов и инвалидация (`FR-14`) |
| Tailwind CSS 4 | дизайн-токены и утилиты |
| Recharts | столбчатые диаграммы |
| ExcelJS | выгрузка XLSX |
| jsPDF + jspdf-autotable | выгрузка PDF |
| Golos Text, JetBrains Mono | шрифты, self-hosted для закрытого контура |
| Playwright | скриншоты и проверка выгрузок при разработке |

Внешних CDN нет: шрифты и иконки лежат в сборке, интерфейс работает без
доступа в интернет.
